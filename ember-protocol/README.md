# 余烬协议 · Ember Protocol

协作开发前请先阅读仓库根目录的 [项目与团队说明](../README.md)、[Agent 规范](../AGENTS.md) 和 [协作流程](../CONTRIBUTING.md)。本文聚焦游戏运行与技术说明。

俯视角射击闯关 Demo。当前包含完整的三关流程：移动射击 → 清怪 → 捡枪 / 选技能 → 传送 → Boss → 结算。

## 开始试玩

需要 Node.js 22.12+。在此目录运行：

```powershell
npm.cmd ci
npm.cmd run dev
```

打开 **http://localhost:5173**。已经安装依赖时，也可以双击 `启动游戏.cmd`，再打开终端显示的地址。

每次双击 `启动游戏.cmd`，脚本都会调用 `start-game.ps1`，先结束正在监听 5173 的旧进程，等待端口释放，再启动新的游戏服务。该脚本需要 Node.js 22.12+ 和 PowerShell 7；如果无法结束占用端口的进程，会给出中英文错误信息并停止。

这是本机试玩地址，其他人的电脑不能通过这个 localhost 地址加入。当前不包含真人联机。

| 操作                            | 键位                            |
| ------------------------------- | ------------------------------- |
| 移动                            | WASD / 方向键                   |

建议先选“AI 战友”熟悉节奏。橙色人物是玩家，绿色人物是 AI。发光枪械和绿色芯片需要靠近后按 E；回血物品接近时自动拾取。右侧椭圆传送门会在两波敌人清空后亮起，靠近后按 E。

## 本版规则

- 3 个固定房间、6 波敌人、43 个敌人；第三关有双阶段 Boss。
- 三把枪：游骑兵突击步枪、破门者霰弹枪、离子蜂脉冲枪。
- 六种技能：连锁电弧、霜冻弹芯、贯穿弹道、闪避新星、战地修复、过载机匣。
- 前两关各有一个战斗掉落模块和一个清关模块。每次随机三选一，最多装配四个，不重复获得。
- 每次新行动从相同的步枪、100 生命开始；每关补满生命、当前弹匣并恢复闪避。**本次行动拾取的武器和技能保留至行动结束**。失败重开会清空。
- 不做金币、商店、背包负重或局外数值养成；弹药储备无限，弹匣与换弹时间构成战斗节奏。
- AI 协作是体验原型：一个不会倒地的支援战友，跟随并射击；敌人生命增加 20%。没有真人联机、救援或复杂分工。
- 游戏画面采用代码绘制，音乐与音效由 Web Audio 实时合成：准备页是一首独立的慢速环境曲（和弦铺底、低音长音与钟声动机），进入战斗则切换为激昂的战斗主题曲（鼓组、贝斯固定音型、主旋律与上升音效），两首曲目各自从头开始；点击右上角声音按钮可分别调节音乐与音效音量（自动保存在本机），M 键一键静音。没有 CDN、账号或在线素材依赖；生产包可静态托管。
- 当前面向桌面键鼠；窄屏可查看页面，但没有触屏战斗操作。
- 中文和英文覆盖菜单、HUD、任务、关卡、枪械、技能、交互提示与结算。语言切换即时生效，不会重开关卡，并保存在本机浏览器。

## 后续 Feature 边界

必须保留 2D 俯视角、射击闯关 PvE、清怪后进入下一关、单人与合作方向，以及战斗中获取枪械和技能形成构筑的基础玩法。不能改成 3D、第一人称、横版、纯解谜、经营或 PvP 主导的其他游戏，也不能增加金币、商店和永久数值养成。

可以继续增加角色、地图、房间、环境机关、怪物、Boss、技能、枪械、视觉与音效反馈、UI、可访问性、平衡、性能和合作功能。真人合作仍是尚未实现的方向；实现时必须保留单人体验和现有闯关循环。需要改变基础玩法的提案应先由三名组员共同决定，不能作为普通 feature 直接开发。

## 技术与维护

Phaser 4.2.1 + TypeScript 5.9.3 + Vite 8.3.0，版本锁在 `package-lock.json`。

```text
src/
  game/
    config.ts       枪械、技能文案、关卡布局和波次
    types.ts        实体与输入 / 事件类型
    math.ts         几何、连续碰撞、可注入随机源
    simulation.ts   不依赖 Phaser 的战斗模型与状态流转
    scene.ts        Phaser 生命周期、键鼠输入缓冲
    renderer.ts     场景、人物、怪物、枪械和粒子呈现
    audio.ts        可关闭的合成音效
  ui/
    interface.ts    主菜单、HUD、技能选择、暂停和结算
    icons.ts        界面 SVG
  i18n.ts           中英文界面词典、语言切换与本地偏好
  main.ts           组装游戏
  style.css         响应式布局和视觉样式
tests/
  combat.test.ts    核心战斗与完整行动流程回归
  i18n.test.ts      中英文词典、插值变量与配置文案完整性
docs/
  DESIGN.md         玩法设计、框架取舍及后续验证方向
```

增加枪械和关卡首先修改配置；新技能同时增加行为、说明和针对性测试。模拟层不访问 DOM、Phaser 或音频，显示层通过事件响应战斗。随机源可注入，使回归测试可复现。后续体量增长时，再按敌人行为、技能效果、投射物拆出独立系统；当前保留一个明确的状态所有者，避免过度抽象。

所有新增或修改的玩家可见内容必须同时提供中文和英文。静态界面文案放在 `src/i18n.ts`；枪械、技能和关卡文案使用 `LocalizedText` 写在 `config.ts`。不要在 UI 或战斗逻辑中直接写单语提示。`tests/i18n.test.ts` 会检查词典键、插值变量以及配置文案是否双语齐全。

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run format:check
npm.cmd run preview
```

`build` 先执行严格 TypeScript 检查，再输出 `dist/`。Phaser 单独打包以便缓存。测试覆盖碰撞、走位、冲刺、弹药、拾取、技能、暂停、AI、失败重开以及三关完整通关。流程测试使用高生命测试夹具并直接安排拾取位置，验证可达性，不代表玩家难度测试。
